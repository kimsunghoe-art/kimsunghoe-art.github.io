## 프로젝트

### 1. 이두런처 (캡스톤 디자인)
- 기간 / 인원: 2026.03 ~ 진행 중 / 3인
- 내 역할: 팀장, 개발 참여
- 팀 구성: 보안학과는 아이디어 구상, 소프트웨어학과는 개발 위주 (모두 개발에 참여)
- 진행 방식: 아이디어가 있으면 그때 들어 보고 계획을 세움
- 사용 기술: AI를 이용한 바이브 코딩

**한 줄 소개**
디지털 취약계층이 스마트폰 문자를 보내는 것도 힘들어해서, 최소한의 기능만 담은 앱을 구상

**겪은 문제와 해결**
- 문제 1: 팀원 모두 학생이다 보니 일정이 달랐음
- 문제 2: 개발 초기에 AI 구독 지원을 받지 못함
- 해결: 개인 자금 사용, 무료로 쓸 수 있는 도구 활용

**결과**
현재 개발 중

**배운 점**
- 지속적인 소통이 있어야 함
- 겸손: 못하는 것은 못한다고 말하는 게 중요하고, 필요하면 필요하다고 말해야 함
- 예산은 조건을 보기 때문에, 다른 곳에 쓸 수 있는 것은 지원해 주지 않는다는 것

### 2. 레시피 공유 앱 (팀 프로젝트)
- 기간 / 인원: 약 3~6개월 / 4인
- 내 역할: 냉장고 기능 개발 (냉장고 안에 들어가는 재료 기능을 가볍게 만듦)
- 사용 기술: Spring Boot, Java, IntelliJ, dbdiagram

**한 줄 소개**
자취생들이 음식을 최대한 좋게 맞게 먹도록 관리를 도와주고 편하게 해 주는 앱. 마지막에는 유튜브 같은 동영상 연동까지 됨

**겪은 문제와 해결**
- 문제: 개발 가능한 인력이 모든 과정을 겪어 본 4학년 선배 한 명뿐이었고, 팀원들의 의욕과 의견 차이도 있었음
- 해결: 앱을 한 번 만들었다가, 6개월 개발 기간 중 3개월 동안 다시 한 번 만듦

**결과**
완성

**배운 점**
- 아이디어를 만들 때 시장 틈새를 계속 찾다 보면, 경쟁자가 없을 정도의 아이디어는 아무도 사용하지 않을 정도이고
- 경쟁자가 있다면 아직 졸업하지 않은 대학생들로는 그만한 서비스를 만들기가 굉장히 힘들다(드물다)
- 서비스를 할 거라면 정말 다양한 조사를 해야 한다
